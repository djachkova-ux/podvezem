# ТЗ: веб-приложение "Школьный трансфер"

Статус: черновик v1, на согласование
Дата: 2026-09-02

## 1. Суть

PWA (веб-приложение, добавляемое на экран телефона через "Добавить на главный экран") для жителей посёлка, чьи дети учатся в одной школе. Позволяет:
- водителям, которые в этот день везут детей, предложить свободные места;
- родителям, которым нужен трансфер, найти водителя (или оставить запрос и дождаться отклика водителя).

Один и тот же взрослый может в разные дни быть то водителем, то заказчиком.

Публикация в App Store / Google Play не требуется. Установка — через браузер (Add to Home Screen), push-уведомления через Web Push (см. ограничение iOS в п. 8).

## 2. Технический стек

- **Frontend:** React + Vite, адаптивная вёрстка mobile-first
- **Backend/данные:** Firebase — Firestore (база), Authentication, Cloud Messaging (push), Hosting
- **Аутентификация:** телефон + пароль, без SMS-подтверждения кода. Реализовано через Firebase Auth Email/Password: телефон превращается в служебный email вида `<цифры телефона>@transfer.local`, пользователь его не видит (решение S2)
- **Регистрация:** открытая, без модерации админом (на будущее закладываем поле-задел под роль admin/блокировку пользователя, но в v1 не реализуем UI для этого)

## 2.1 Дизайн (утверждено 02.09.2026)

Направление — **«Хвоя»**: тетрадь в клетку + табло отправлений. Макет доски водителей: `design/board-drivers.html`, токены для кода: `design/tokens.css`.

- **Палитра.** Хвойный `#1F5140` — единственный громкий цвет, только на главное действие («Откликнуться», кнопка новой поездки, сегодняшний день). Латунь `#B8912A` — служебные акценты (точки маршрута, активная вкладка). Нейтрали подкрашены в зелёный: фон `#ECF0EB`, текст `#16241C`. Смысловые цвета отдельно: есть места `#2E7D5B`, мест мало `#B4622B`, ждёт подтверждения `#5A66A0`.
- **Очереди** имеют закреплённые цвета во всём приложении: 1 — `#35707F`, 2 — `#97731D`, 3 — `#7A5A9C`.
- **Тёмная тема** пересчитана отдельно (не инверсия), реагирует на системную настройку и на ручной выбор через `data-theme`.
- **Шрифты.** Golos Text — весь интерфейс (спроектирован под кириллицу). Oswald — только время и служебные метки, узкий «вокзальный» голос. Оба с Google Fonts.
- **Ключевые приёмы доски.** Маршрутный пунктир слева с точкой-остановкой на каждый рейс; время — самый крупный элемент карточки, табличными цифрами; свободные места — пиктограммы сидений (занято/свободно), а не только число; состояние всегда закодировано дважды — цветом и словом.

## 3. Роли и статусы

Один аккаунт = один взрослый (родитель/сосед). У аккаунта могут быть одновременно включены два статуса:

- **Водитель** — может отвозить детей. Доступен вместе со статусом "Заказчик".
- **Заказчик** — которому нужен трансфер для своего ребёнка/детей. Доступен вместе со статусом "Водитель".
- **Пассажир** — это сам ребёнок, не отдельный аккаунт, а запись в профиле заказчика (Имя, возраст). Пассажир не может быть одновременно водителем или заказчиком (это не роль аккаунта, а сущность "ребёнок").

Взрослый по умолчанию регистрируется как "Заказчик" и опционально включает у себя в профиле "Водитель" (тогда открывается форма авто).

## 4. Профиль пользователя

Общее:
- Имя
- Телефон
- Очередь(и) — см. п.5

Если включён статус "Водитель", дополнительно:
- Гос. номер автомобиля
- Марка автомобиля
- Цвет автомобиля
- Список очередей, откуда готов забирать (можно несколько)

Если включён статус "Заказчик", дополнительно:
- Адрес, откуда забирать ребёнка
- Очередь проживания (одна)
- Список детей: Имя, возраст (можно добавлять/удалять)

## 5. Очереди

Посёлок технически делится на 3 территории — "очередь": 1, 2, 3.
- Водитель указывает, из каких очередей может забирать детей (мультивыбор).
- Заказчик указывает только одну очередь — где проживает.
- Очередь заказчика показывается водителю при отклике на его запрос / при просмотре отклика на своё предложение.

## 6. Доски

Две доски: **"Водители"** (предложения трансфера) и **"Запросы"** (заявки на трансфер).

Общее для обеих досок:
- По умолчанию показывается текущая дата, есть возможность выбрать другую дату.
- Фильтр по смене: 1 смена (08:00–12:29) и 2 смена (12:30–19:00).
- Карточка на доске пропадает, когда предложение/запрос закрыт (см. п.7, п.8).

### 6.1 Доска "Водители"
Карточка предложения показывает: дату, время прибытия в школу, водителя (имя, авто), очереди, из которых забирает, количество свободных мест (уменьшается по мере подтверждения откликов).

Создание предложения (доступно водителю):
- Дата, время прибытия в школу, количество свободных мест
- Опция "Повторять" — задать шаблон на дни недели + время на период вперёд (например, месяц), предложения на эти дни генерируются автоматически

### 6.2 Доска "Запросы"
Карточка запроса показывает: дату, время, нужную заказчику очередь, количество детей, адрес (виден только водителям, откликнувшимся/просматривающим детали), опционально комментарий.

Создание запроса (доступно заказчику): дата, время прибытия в школу, количество детей (выбираются из своего списка детей).

## 7. Отклики заказчика на предложение водителя

1. Заказчик находит предложение на доске "Водители", открывает отклик.
2. Указывает: каких детей везёт (мультивыбор из своего списка, но не больше, чем свободных мест у водителя), необязательный комментарий.
3. Статус отклика: "Ожидает подтверждения".
4. Водитель видит отклики на своё предложение (список: заказчик, очередь, адрес, дети, комментарий) и подтверждает или отклоняет каждый.
5. При подтверждении: свободные места у предложения уменьшаются на кол-во подтверждённых детей. Когда места кончились — предложение закрывается и уходит с доски.
6. Подтверждённый отклик появляется в профиле заказчика и водителя как активная поездка.
7. Заказчик может снять уже подтверждённый резерв (отменить поездку) — места у водителя возвращаются, предложение может снова появиться на доске, если было закрыто.

## 8. Отклики водителя на запрос заказчика

1. Водитель находит запрос на доске "Запросы", отправляет отклик (сообщение), комментарий необязателен.
2. Заказчик видит отклики на свой запрос (водитель, авто, очереди) и подтверждает нужный (можно один, если это закрывает потребность).
3. При подтверждении запрос закрывается и уходит с доски, поездка появляется в профилях обеих сторон как активная.
4. Симметрично п.7.7 — заказчик может отменить подтверждённую поездку.

## 9. Активные поездки и завершение

- И водитель, и заказчик видят в профиле список подтверждённых (активных) поездок — до момента завершения.
- Только водитель может завершить поездку кнопкой "Закончить поездку" → статус "Доставлен". После этого поездка уходит из "активных" в историю (архив) обеих сторон.

## 10. Уведомления

Push-уведомления (Web Push / Firebase Cloud Messaging) на рабочий стол телефона/компьютера, где открыто приложение:
- Новый запрос на трансфер появился на доске — всем водителям (или хотя бы тем, кто включил уведомления/подходит по очереди — уточняется в разработке).
- Новое предложение трансфера появилось — всем заказчикам аналогично.
- Новый отклик на моё предложение / мой запрос — автору предложения/запроса.
- Подтверждение или отклонение моего отклика — автору отклика.
- Отмена подтверждённой поездки — второй стороне.

**Важное ограничение:** на iPhone push-уведомления для веб-приложений работают только если сайт добавлен на "Домой" через Safari (iOS 16.4+) и открыт как отдельное приложение — из обычной вкладки браузера push не работает. На Android ограничений нет. Это нужно будет объяснить пользователям при инструктаже.

## 11. Что уточняем в процессе разработки (не блокирует старт)

- Нужен ли админ-режим (блокировка пользователя, модерация) — в v1 не делаем, но модель данных закладывает под это поле.
- Как именно фильтровать получателей уведомления о новом запросе/предложении (все vs подходящие по очереди) — по умолчанию всем, можно сузить позже.
- Нужна ли история/статистика поездок за месяц.

## 12. План сессий (ориентировочно 8–12)

1. Каркас проекта (React+Vite), Firebase (Auth, Firestore, Hosting), регистрация, профили, роли, очереди
2. Доска "Водители" + создание предложения + фильтры (дата/смена)
3. Доска "Запросы" + создание запроса + фильтры
4. Отклики заказчик→предложение, подтверждение водителем, авто-уменьшение мест, закрытие предложения
5. Отклики водитель→запрос, подтверждение заказчиком, закрытие запроса
6. Активные поездки в профиле, отмена резерва, "Закончить поездку" / архив
7. Повторяющиеся предложения (шаблон на дни недели/месяц)
8. Push-уведомления (service worker, FCM), все 4 сценария из п.10
9–10. Мобильная полировка UI, тестирование на реальных телефонах (Android/iOS), правки
11–12. Запас на непредвиденное / доп. правки по итогам обратной связи от первых пользователей
