Дата: 03.09.2026. Сессия: **S4 — создание предложения**.

## Что сделано в S4

Водитель может опубликовать поездку прямо с доски.

- **`src/screens/NewOffer.jsx`** (новый) — форма создания предложения: дата (`<input type="date">`, `min` = сегодня), время прибытия (`<input type="time">`), свободные места (select 1–8), необязательный комментарий. Данные о водителе (`name`, `phone`, `car`, `pickupQueues`) не вводятся заново — берутся снимком из профиля в момент публикации (тот же принцип денормализации, что и в сид-скрипте S3).
- **Гейт доступа:** если `profile.isDriver` не включён, или не заполнены `car.plate`/`pickupQueues`, экран вместо формы показывает подсказку с кнопкой-ссылкой на `/profile`. Это чисто клиентская проверка UX — на уровне Firestore rules ограничений по заполненности профиля нет (не требовалось: `driverId == request.auth.uid` в правилах уже не даёт создать предложение от чужого имени).
- **`src/lib/db.js`** — `createRideOffer(uid, profile, { date, arrivalTime, seatsTotal, note })`: пишет в `rideOffers` документ со `status: 'open'`, `seatsFree = seatsTotal`, `createdAt: serverTimestamp()`. Поле `note` попадает в документ, только если непустое.
- **Маршрут** `/board/drivers/new` в `App.jsx` — доступен и через FAB, и напрямую по URL.
- **FAB «+ Поездка»** на `DriversBoard.jsx` — виден только пользователям с `profile.isDriver`. Технически — второй элемент Fragment рядом с `<main className="screen">`, а не внутри него: FAB должен оставаться на месте при прокрутке доски, а `.screen` — это именно прокручиваемый контейнер (`overflow-y: auto`). `position: absolute` у `.fab` целится в `.app` (`position: relative` в `base.css`), поэтому FAB и `.screen` должны быть братьями, не родитель-потомок.
- **`Icon.jsx`** — добавлена иконка `plus` (путь из `design/board-drivers.html`, символ `#ic-plus`).
- **`AppHead.jsx`** — сегментированный переключатель «Водители/Запросы» раньше показывался на любом пути, начинающемся с `/board` (`startsWith`), из-за чего вылезал бы и на `/board/drivers/new`. Заменено на точное совпадение пути с одним из двух адресов досок.
- **`board.css`** — стили `.fab`, перенесены из макета, но с поправкой под реальную вёрстку: в макете `.fab` позиционировался от `bottom: 88px` в предположении, что нижняя навигация — `position: absolute` внутри телефонного фрейма. В реальном приложении `.tabbar` стоит в обычном потоке (`flex: none`), поэтому отступ снизу считается как `calc(env(safe-area-inset-bottom) + 78px)` — с запасом под её реальную высоту.
- **Проверено в браузере** (см. раздел про порт ниже): вход тестовым водителем `+7 900 222-33-01` / `test1234`, клик по FAB → форма → публикация предложения на 09:15, 3 места, комментарий «Проверка S4» → мгновенно появилось на доске (счётчик «4 поездок·9 мест» → «5 поездок·12 мест», новая карточка с очередями и авто, взятыми из профиля Ирины Ковалёвой, с пометкой «Это ваша поездка»). Прямой переход по URL на `/board/drivers/new` тоже открывает форму (не только через FAB).
- **Не проверено вживую:** ветка гейта «вы не водитель / профиль не заполнен» — логика простая (три булевых условия), но кликом в браузере не прогонялась (потребовался бы отдельный тестовый аккаунт без роли водителя).

## Побочное: конфликт порта dev-сервера

При проверке в браузере порт 5173 оказался занят чужим dev-сервером (в этой же папке была открыта ещё одна сессия Claude Code). Пользователь выбрал вариант «временный другой порт». Из-за этого:

- **`.claude/launch.json`** — добавлено `"autoPort": true` в конфигурацию `podvezem-dev`.
- **`vite.config.js`** — `port: 5173` заменено на `port: Number(process.env.PORT) || 5173`. Обратно совместимо: без переменной `PORT` в окружении поведение не меняется, `npm run dev` по-прежнему поднимается на 5173.

Оставлено как есть — правки безобидные и не мешают штатной работе `npm run dev`.

## Принятые решения (накопительно)

- Схема `rideOffers` не изменилась с S3 (см. предыдущие хэндоффы): `driverId`, `driverName`, `driverPhone`, `driverCar {plate, brand, color}`, `pickupQueues[]`, `date`, `arrivalTime`, `pickupQueues[]`, `seatsTotal`, `seatsFree`, `note?`, `status`, `createdAt`.
- Форма создания предложения не даёт задать очереди отдельно от профиля — очереди водителя (`pickupQueues`) на момент публикации копируются из профиля целиком, без выбора подмножества на конкретную поездку. Если это когда-то понадобится (водитель в этот день забирает не из всех своих обычных очередей) — потребуется доработка формы, сейчас не заложено.
- FAB условно рендерится только для `profile?.isDriver` — заказчики его не видят на доске водителей.
- Опция «Повторять» из ТЗ 6.1 сюда сознательно не входит — она в S9 (повторяющиеся предложения).
