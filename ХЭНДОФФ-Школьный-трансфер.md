# Хэндофф · «Подвезём» (школьный трансфер)

Дата: 03.09.2026. Сессия: **S5 — доска запросов и создание запроса**.

## Что сделано в S5

Вторая доска, парная «Водителям»: заказчик публикует запрос на трансфер, водители видят его на доске «Запросы».

- **`src/lib/db.js`** — добавлены `subscribeRequests(dateKey, callback)` (подписка на коллекцию `requests` по `date`+`status: 'open'`, сортировка по времени на клиенте — тот же паттерн, что и `subscribeRideOffers` в S3, без составного индекса) и `createRequest(uid, profile, { date, arrivalTime, childrenIds, note })`. Данные заказчика (`customerName`, `customerPhone`, `address`, `homeQueue`) — снимком из профиля на момент публикации; `children` — не весь список, а выбранное подмножество `profile.children`, отфильтрованное по `childrenIds` из формы.
- **`firestore.rules`** — новый блок `requests`: читают все авторизованные, создаёт и меняет только сам заказчик (`request.auth.uid == ...customerId`). **Важно: правила изменены только в файле, в консоли Firebase ещё не опубликованы** — см. раздел «Осталось сделать» ниже.
- **`src/components/RequestCard.jsx`** (новый) — карточка запроса. Сознательно переиспользует существующие классы из `board.css` (`.ride-card`, `.ride-top`, `.who`, `.avatar`, `.name`, `.car`, `.queues`, `.note`, `.actions`, `.own-note`) без единой новой строки CSS — карточка запроса и карточка предложения визуально из одного семейства. Показывает: время + смену, аватар с инициалами заказчика, количество и имена детей (строка с классом `.car`, переиспользован как «вторая строка под именем», хоть и назван по смыслу предложений — в разметке это универсальный сероватый текст), домашнюю очередь (`QueueTag`), комментарий. Адрес по п. 6.2 ТЗ виден только владельцу запроса (`isOwn`) — остальным вместо адреса заглушка «Адрес будет виден после отклика». Кнопка «Откликнуться» неактивна (как и на карточке предложения в S3/S4) — отклики водителя появятся в S7. Телефон заказчика в карточке не показывается — в отличие от `RideCard`, где телефон водителя виден всем, ТЗ для запроса телефон в списке полей карточки не упоминает.
- **`src/screens/RequestsBoard.jsx`** (переписан с плейсхолдера) — по структуре точная копия `DriversBoard.jsx`: `DateStrip`, `ShiftFilter`, счётчик «N запросов · M детей» (своя функция `childrenWord` с русским склонением 1/2-4/5+, отдельная от `RideCard`, но по такому же принципу, что и `seatsWord` в `DriversBoard`), список карточек в `.route`. **Одно смысловое отличие от доски водителей:** чип «Моя очередь» в `ShiftFilter` здесь показывает не единственную `homeQueue` пользователя, а список `pickupQueues` водителя (`profile.pickupQueues.join(', ')`, например «Моя очередь · 1, 2»), и фильтрует запросы, чья `homeQueue` входит в этот список — потому что доску запросов смотрят в первую очередь водители, выбирающие, кого забрать. Сам компонент `ShiftFilter.jsx` не менялся — `homeQueue`-проп в нём просто строка для подписи чипа, семантика на его стороне не зашита.
- **`src/screens/NewRequest.jsx`** (новый) — форма: дата (`min` = сегодня), время прибытия, мультивыбор детей чекбоксами (`.checkbox-group`/`.checkbox-chip`, тот же класс, что и для очередей водителя в `Profile.jsx`), необязательный комментарий. Гейт: `profile.isCustomer && profile.address && profile.children.length > 0` — иначе подсказка со ссылкой на профиль (тот же паттерн, что и гейт водителя в `NewOffer.jsx` из S4). Валидация «выберите хотя бы одного ребёнка» — на клиенте, до вызова `createRequest`.
- **FAB «+ Запрос»** на `RequestsBoard.jsx` — виден только `profile?.isCustomer`, та же структура «FAB как сосед `.screen`, а не потомок» из S4 (см. хэндофф S4 про `position: absolute` относительно `.app`).
- **Маршрут** `/board/requests/new` в `App.jsx`. `AppHead.jsx` не трогали — переключатель «Водители/Запросы» и так сравнивается по точному совпадению пути (правка была уже в S4), поэтому на `/board/requests/new` сегментированный переключатель корректно не показывается без дополнительных условий.

## Принятые решения (накопительно)

- Схема `requests`: `customerId`, `customerName`, `customerPhone`, `address`, `homeQueue`, `children[]` (снимок выбранных `{id, name, age}`, не весь список семьи), `date`, `arrivalTime`, `note?`, `status`, `createdAt`.
- Адрес в карточке запроса скрыт от всех, кроме владельца, до появления откликов (п. 6.2 ТЗ) — реализовано клиентской проверкой `isOwn`, как и раньше без ограничений на уровне Firestore rules (в rules ограничений на видимость отдельных полей документа нет и не будет — Firestore rules не умеют скрывать поля, только весь документ; если понадобится настоящее ограничение на уровне сервера, придётся выносить адрес в подколлекцию с отдельными правами — не делали, не требовалось для S5).
- Телефон заказчика в `requests`-документе хранится (пригодится для S7 — отклик водителя), но нигде не отображается в S5.
- Чип «Моя очередь» на доске запросов имеет другую семантику, чем на доске водителей (список `pickupQueues` водителя вместо одной `homeQueue` заказчика) — компонент `ShiftFilter` от этого не менялся, разница только в данных, которые ему передают экраны.
