# Трекер разработки «Подвезём»

Один пункт плана = одна сессия Claude Code. Задача трекера — чтобы **сессия не превышала ~200 000 токенов** и следующая начиналась без пересказа предыдущей.

Как стартовать сессию: открыть новый чат в папке проекта и написать
`Читай ТРЕКЕР-РАЗРАБОТКИ.md, делаем сессию S2` — этого достаточно.

---

## Правила экономии контекста (главное)

1. **Читать только то, что перечислено в блоке «Читать» текущей сессии.** Остальные файлы — через `Grep`/`Glob`, а не целиком.
2. **Никогда не читать целиком `design/board-drivers.html`** (~1400 строк, это ≈40 000 токенов). Это визуальный референс: смотреть его в браузере, а цвета и шрифты брать из `design/tokens.css` (~150 строк).
3. **ТЗ читать по разделам**, а не целиком: нужный раздел ищется `Grep` по заголовку (`## 6`, `## 7` и т. д.).
4. **Один файл — одна задача, ≤ 250 строк.** Экран больше 250 строк — выносить куски в `src/components/`. Большие файлы дорого перечитывать в следующих сессиях.
5. **Не открывать** `node_modules/`, `dist/`, `package-lock.json`, содержимое `.firebase/`.
6. **Не вставлять в чат длинные выводы**: сборку и тесты запускать так, чтобы в ответ шли только ошибки (`npm run build 2>&1 | Select-Object -Last 20`).
7. **Не переписывать файл целиком ради правки в двух строках** — точечные `Edit`.
8. **Правило 60 %:** как только израсходовано около 60 % контекста, а сессия не закончена — не начинать новую подзадачу. Довести текущую до рабочего состояния, обновить трекер, сделать коммит и хэндофф.
9. **Финиш каждой сессии:** отметить статус в таблице ниже → коммит → обновить `ХЭНДОФФ-Школьный-трансфер.md` (перезаписывать, не накапливать).

## S1 · Каркас проекта и Firebase

- **Цель:** пустое, но работающее приложение с нижней навигацией и подключённым Firebase.
- **Читать:** `design/tokens.css`, ТЗ раздел 2 и 2.1.
- **Не читать:** макет `design/board-drivers.html`.
- **Файлы:** `package.json`, `vite.config.js`, `index.html`, `src/main.jsx`, `src/App.jsx`, `src/firebase.js`, `src/styles/*`, `.env.example`, три пустых экрана + `TabBar`.
- **Готово когда:** `npm run dev` открывается, переключаются три вкладки, Firebase инициализируется без ошибок в консоли.
- **От пользователя нужно:** созданный проект в Firebase Console и ключи из настроек веб-приложения (в `.env.local`, он в `.gitignore`).
- **Сделано:** React 19 + Vite 8 + react-router 7 + Firebase 12. Маршруты: `/board/drivers`, `/board/requests`, `/trips`, `/profile`; вкладок в навигации три (доска переключается сегментами в шапке). Пока нет `.env.local` — приложение не падает, показывает предупреждение (`firebaseReady` из `src/firebase.js`).
- **Осталось:** ничего — ключи подставлены, Firebase-проект `podvezyom` создан (Authentication: Email/Password, Firestore: production mode, регион eur3), в браузере проверено, что инициализация проходит без ошибок в консоли.

## S2 · Регистрация, вход, профиль

- **Цель:** телефон + пароль без SMS, профиль с ролями, очередями, авто и детьми.
- **Читать:** ТЗ разделы 2–5, `src/firebase.js`.
- **Файлы:** `src/lib/auth.js`, `src/screens/Login.jsx`, `Register.jsx`, `Profile.jsx`, `src/components/ChildrenList.jsx`, правила Firestore.
- **Готово когда:** можно зарегистрироваться, включить «Я водитель», заполнить авто, добавить детей; данные видны в Firestore.
- **Развилка:** телефон как логин делается через служебный e-mail вида `<цифры телефона>@transfer.local` в Firebase Auth — записать решение в ТЗ.
- **Сделано:** `src/lib/phone.js`, `auth.js`, `db.js`, `constants.js`; `src/context/AuthContext.jsx`; экраны `Login.jsx`, `Register.jsx`, переписан `Profile.jsx`; `src/components/ChildrenList.jsx`; `src/styles/forms.css`; `firestore.rules` (правила опубликованы в консоли вручную — CLI-деплоя ещё нет). `App.jsx` гейтит неавторизованных на `/login`. Полный цикл регистрация → профиль (ребёнок + авто) → выход → вход → данные на месте проверен в браузере.

## S3 · Доска водителей

- **Цель:** экран из макета на реальных данных.
- **Читать:** `design/tokens.css`, ТЗ раздел 6.1. Макет — только в браузере.
- **Файлы:** `src/screens/DriversBoard.jsx`, `src/components/RideCard.jsx`, `SeatMeter.jsx`, `QueueTag.jsx`, `DateStrip.jsx`, `ShiftFilter.jsx`, `src/lib/db.js`.
- **Готово когда:** доска читает `rideOffers` из Firestore, работают выбор даты и фильтр смен; тестовые данные засеяны скриптом.
- **Сделано:** `src/lib/dates.js` — `getDateStrip`, `getShift`, `SHIFTS`; `src/lib/db.js` — `subscribeRideOffers` (запрос по `date`+`status`, сортировка по времени на клиенте, без составного индекса); `firestore.rules` — блок `rideOffers` (читают все авторизованные, пишет только водитель-владелец), опубликован в консоли. Компоненты `DateStrip.jsx`, `ShiftFilter.jsx` (смены + чип «Моя очередь»), `QueueTag.jsx`, `SeatMeter.jsx`, `RideCard.jsx`; иконки `seat`/`seatFilled`/`phone`/`clock` добавлены в `Icon.jsx`. `DriversBoard.jsx` переписан на реальные данные. Стили — новый `src/styles/board.css`. Кнопка «Откликнуться» на карточке — не активна (отклики появятся в S6), кнопка звонка работает по `tel:` сразу. Кнопка создания предложения (FAB) в S3 не добавлена — появится вместе с экраном в S4. Сид-скрипт `scripts/seed-ride-offers.mjs` (`npm run seed:ride-offers`) создаёт 4 тестовых водителей и 6 предложений на сегодня/завтра/послезавтра. Проверено в браузере: полоса дат, фильтр смены, фильтр «Моя очередь» — все работают, доска даёт ожидаемую выборку.

## S4 · Создание предложения

- **Цель:** водитель публикует поездку.
- **Читать:** ТЗ раздел 6.1, `src/lib/db.js`.
- **Файлы:** `src/screens/NewOffer.jsx`, дополнения в `db.js`.
- **Готово когда:** созданное предложение сразу появляется на доске. Повтор по дням недели — не здесь, он в S9.
- **Сделано:** `src/screens/NewOffer.jsx` — форма (дата, время прибытия, свободные места, необязательный комментарий); данные о водителе/авто/очередях берутся снимком из профиля, не вводятся заново. Гейт: если `profile.isDriver` не включён или не заполнены авто/очереди — экран показывает подсказку со ссылкой на профиль вместо формы. `src/lib/db.js` — `createRideOffer(uid, profile, data)`. Маршрут `/board/drivers/new` в `App.jsx`. FAB «+ Поездка» на `DriversBoard.jsx` (виден только водителям), стили в `board.css`. Иконка `plus` добавлена в `Icon.jsx`. `AppHead.jsx` — сегментированный переключатель «Водители/Запросы» теперь показывается только на самих досках (точное совпадение пути), а не на любом `/board/*` подэкране. Проверено в браузере: публикация предложения тестовым водителем сразу отражается на доске (счётчик мест и новая карточка), прямой переход по URL на `/board/drivers/new` тоже работает.

## S6 · Отклики заказчика → подтверждение водителем

- **Цель:** ключевая логика приложения, самая аккуратная сессия.
- **Читать:** ТЗ раздел 7, `src/lib/db.js`.
- **Файлы:** `src/screens/RespondSheet.jsx`, `src/screens/OfferResponses.jsx`, транзакции в `db.js`.
- **Готово когда:** отклик с выбором детей не превышает свободные места; подтверждение уменьшает места **транзакцией**; при нуле предложение закрывается и уходит с доски.
- **Осторожно:** два одновременных подтверждения не должны увести места в минус — только `runTransaction`.

## S7 · Отклики водителя → подтверждение заказчиком

- **Цель:** зеркальный сценарий.

- **Готово когда:** подтверждённый отклик закрывает запрос и создаёт активную поездку у обеих сторон.

## S8 · Мои поездки, отмена, завершение

- **Читать:** ТЗ раздел 9.

## S9 · Повторяющиеся предложения

## S10 · Push-уведомления

- **Читать:** ТЗ раздел 10.
- **Файлы:** `public/firebase-messaging-sw.js`, `src/lib/notifications.js`, Cloud Functions (или триггеры на клиенте — решить в начале сессии).
